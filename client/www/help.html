Top bar

The bar above is present on every page.
• The dark pill on the right shows the height of the chain; it pulses when a new block arrives. Hover over it to see when the last block arrived.
• shows up while the chain is not in sync. Click on it to enter the hash of the highest block you trust - the blocks up to that one are then marked as trusted, so the node does not verify their signatures, which speeds the sync up considerably.
• - beep on each new block.
• The sun/moon button switches between the light and the dark theme.
• Each menu item has an access key, so you can jump between the pages with Alt+1 ... Alt+9.

Wallet and Spend are greyed out whenever the wallet functionality is off.

Home

 The node's dashboard.

WebUI Settings

Export (backup) the current settings of the web interface to a JSON file.
Import (restore) the settings from a previously created JSON file.
The settings include all the wallets from the Wallet page and the address book from the Spend page.
The checkbox next to them makes the WebUI follow your system's light/dark mode automatically.

Recent Blocks

A chart of the recently received blocks. Choose what to plot: Average SPB, Blocksize KB, Transactions or Weight. Tick bl. avg to add a moving average line and Ord. % to see how much of the block space is taken by Ordinal Inscriptions.

Last Block / Network / Node

Details of the most recently accepted block, the current bandwidth and connection counters, your external IP, plus the node's uptime, memory usage and the state of the transaction memory pool.
Click to release as much memory as possible back to the system.

Edit config / Save config

Edit config opens the config file (JSON format) for editing. Change the values you need and press either Apply or Apply & Save. If you do not save, the changes will be lost at the next shut down of the node.
Save config stores the current settings - use it whenever you have changed something in a running node (e.g. on the Network or Mempool page) and you want to keep it permanently.
Some config values are only applied after a restart.

Restart node / Shutdown

Restart node stops and relaunches the node.
Shutdown stops it for good. After the shutdown you will not be able to start the node again from the web interface.

Auth Key

Your node's Public Authorization Key, shown at the bottom of the Network box. Click it to copy.
Place this value in the friends.txt file of another gocoin node, to make it trust yours. Trusted nodes respond to the getmp command and do not re-verify the blocks and transactions they receive from you.

Wallet

 Balance of your (watch-only) wallets. Note that the wallets' data is only stored inside your browser.

Your wallets

Each of the wallets stored in your browser gets a button in the Available wallets row - click it to switch. Use Move left / Move right to reorder and Delete This Wallet to remove the current one.
Edit lets you rename the wallet and edit its list of addresses. Only list public addresses there - one per line, optionally followed by a label. Lines starting with # are ignored, except for # SegWit, # SegWit P2SH and # SegWit Tap which switch the format that the following change addresses get translated to in Spend.

Current wallet

The total balance and the balance of each individual address.
Click on to see the QR code of the corresponding address.
Download balance.zip to use the current balance with gocoin's wallet tool.
Tick Show unconfirmed to also account for the wallet's transactions that are still in the memory pool.
If MinValue is set in the config file, outputs below it are not tracked and a warning is displayed.

Address formats

Click on the first column's header to switch between Public Key, Old / P2KH and New / P2TAP (the first and the last one require a wallet with raw public keys).
Click on the segwit column's header to switch it between the backward compatible P2SH-P2WPKH and the native bech32 P2WPKH format.
All these addresses are derived from the same keys, so you can deposit to any of them and still spend it with gocoin's wallet.

Turn wallet functionality off

Disable the wallet to save memory and speed up block chain processing. Switching it on and off does not require a restart, but may take a while.

Spend

 Create a transaction to be signed by gocoin's wallet tool.

Select Inputs

First go to the bottom of the form, choose the wallet and tick the unspent outputs you want to spend.
Together they must carry enough BTC to cover all the outputs and the fee.
All the selected inputs go into one transaction, no matter what amounts you enter above.

Payment details

Fill in the outputs (address - BTC value); use +add output and -remove last to change their number.
Edit Address Book stores your frequently used addresses in the browser. The button next to each output opens a list to pick one of them from, and it shows the label whenever the address you typed in is a known one.
Sequence is the input sequence number: the default -3 marks the transaction as replaceable (RBF), while -1 or -2 makes it final.
Change selects where the remainder goes. If the address you want is not on the list, add it to the current wallet on the Wallet page.
For the fee, either type the value in, or leave Auto-calc transaction fee ticked and give the price in Satoshis Per Byte - the fee will then follow the estimated size of the transaction.
Note that the estimated transaction size may not be accurate. It assumes compressed public keys and 2-of-3 multisig for P2SH addresses.

Download payment.zip

Press this button to download payment.zip
Move this file to the PC with the wallet tool and extract it there. Then execute the payment command (by default it is in the file pay_cmd.txt).
The wallet tool will create and sign the transaction, just as you have defined it here. Load the signed transaction back into the node with Load TX and broadcast it from the Mempool page.

Network

 The current connections to other bitcoin peers.

Incoming connections

The switch next to Listening for incoming connections allows (or blocks) TCP connections from other nodes.
Note that having this switched on does not automatically mean that external peers will be able to connect to your node.
Configure your network to allow incoming connections at the desired TCP port and route them to the host running the node.

To make the change permanent, Save config at the Home page.

Edit Friends / Unban / Connect Peer

Connect Peer makes an immediate outgoing connection to the given address.
Unban removes a previously banned peer from the black list.
Edit Friends edits the friends.txt file. Valid lines contain hostname:port, @AuthKey, +IP or *AgentPrefix; use # for comments. The node keeps connecting to these peers, does not ban them and does not apply the usual version requirements to them. An @AuthKey entry additionally makes the peer authorized, which is what makes its blocks and transactions trusted.

Bandwidth chart

The download and upload speed over time. Change Resolution to zoom in or out.

Connections table

One row per peer, with its address, age, ping, traffic counters, version and the number of blocks and transactions exchanged.
Tick Freeze table to stop it from updating while you read it, hide the incoming or the outgoing peers, and sort the list by speed or by age.
• shows the detailed statistics of the connection.
• drops the connection and bans the peer.

Mempool

 Memory pool monitoring and broadcasting of your own transactions.

Memory pool chart

Shows how the mempool's content is distributed over the fee rates. Choose the X range: one Block, one Hour or All of the mempool. Limit Y caps the Y axis, so that a few very high fee rates do not flatten the rest of the chart. Quick fetches a simplified chart, using less bandwidth.

Memory pool status

How much RAM the pool takes, its total weight (and how many blocks it would fill), the number of UTXOs spent by the pool's transactions and the current minimum fee rate accepted.
• Rejected transactions - click the button for the list of transactions that were not accepted, along with the reason. The node keeps this list to avoid downloading the same transaction over and over again.
• Waiting for inputs - transactions with the inputs not seen yet, if allowed by TXPool.AllowMemInputs.
• Txs being processed - transactions already received from the network, but not yet handled by the pool.
• Own TXs - shows only the transactions that you have loaded locally.

Memory pool / Relaying transactions

Use the switches to disable the memory pool (the node then only works with full blocks and never downloads any transactions), or to keep the pool while not relaying anything further.
To make the change permanent, Save config at the Home page.

Browsing the pool

Pick how many transactions to display, the field to sort by and the direction, then press show me now.... You can also sort the resulting table by clicking on its column headers.
The Sent column says how many times the transaction's data was sent out to a peer and (after the slash) how many times its inv was announced. If a transaction was blocked from being relayed, the Extras column gives the reason.

Own transactions

Locally loaded transactions appear on a light-red background, at the top of the list, with three extra icons:
• - broadcast to one random peer (useful for privacy purposes)
• - broadcast to all the currently connected peers
• - remove (unload) the transaction from the memory pool

Loading and decoding

Upload Transaction File loads a raw transaction from a file (e.g. the one signed by the wallet tool).
Both of the decoding buttons ask you for a TXID of a transaction that the node already holds.
Decode mempool TX looks the transaction up in the memory pool and shows it broken down into inputs and outputs, together with its raw hexdump.
Decode TX shows the node's own decoding of the transaction and finds it even if it had been rejected, so use this one for the transactions from the Rejected list.

Blocks

 The most recently received blocks.

Switch the right hand side of the table between Mining Information (fees, SPB and the miner) and Block Processing - where you can see which peer the block came from, how many transactions were missing from the compact block and how long each stage of processing took.
Click on the Received / Timestamp header to switch between the two times.

Miners

 Mining statistics from the recent blocks: who mined how many of them, their share, hash rate, average block size and the fees collected.

Below the table you will find the distribution of the block version values and an estimate of the next halving.

Console

 The node's text console, inside the browser - the same commands that you can type in the terminal window.

Type help for the list of the commands, use Tab to complete and Up/Down to browse the history.
The console gives a full control over the node, so it is not available in the server mode.

Load TX

 Load your own transaction into the node's memory pool.
The transaction must be in a hex-encoded raw format, with no spaces nor any other characters except hex digits.

If the operation succeeds you will end up at the Mempool page, which will decode and display the details of your transaction. From there you should broadcast it, in order for the bitcoin network to see it.

Stats

 The node's internal real time counters and statistics.

Switch between the Generic counters and the Network ones (per message type, received and sent). Tick Combine to group similar counters together.
The counters are not collected if Stats.NoCounters is set in the config file.
